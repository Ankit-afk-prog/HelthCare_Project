# Machine Learning-Based Healthcare Facility Performance Classification and Quality Analysis

College CA-III mini-project (healthcare analytics, non-image tabular data).
**Data:** CMS *Inpatient Rehabilitation Facility (IRF)* - General Information and Provider Data (September 2026 refresh).
Source: CMS Provider Data Catalog (https://data.cms.gov/provider-data/). Data dictionary: *IRF QRP Data Dictionary v7.0, Sept 2026*.

> The Low / Medium / High categories are **project-specific analytical performance categories** built from public quality
> measures. They are **not official CMS ratings**. This is a quality-analytics study, **not a clinical decision-support system**.

## Problem statement
Can facility characteristics and quality-related measures be used to analyse and classify IRFs according to data-derived performance?

## Objectives
1. Merge the two CMS files safely at facility (CCN) level.  2. Build a transparent *Quality Performance Index* and tercile categories.
3. Describe and diagnose differences in performance (ownership, region, size).  4. Train LR, Decision Tree, Random Forest, XGBoost.
5. Test a hybrid (soft-voting / weighted / stacking) model against the individual models.  6. Explain predictions with SHAP.  7. Provide a Streamlit dashboard.

## Dataset sources and join
| File | Grain | Rows |
|---|---|---|
| `irf_general_information.csv` | 1 row / facility | 1,222 |
| `irf_provider_data.csv` | 1 row / facility x measure (long) | 79,430 (65 per facility) |

Join key: `CMS Certification Number (CCN)` (1 : 65). The long Provider table is **pivoted to one row per CCN first**, then 1:1 left-joined
(assertions in code guarantee 1,222 rows after merging). The *Conditions* file was not provided/used.

## Methodology
Direction adjustment -> percentile rank -> weighted mean over the available measures (>= 8 of 11) -> tercile categories.
Sensitivity to equal / domain-balanced / PCA weights is reported. **No measure that builds the index is used as a model feature** (leakage control).
* **Design 1 (primary):** index from 11 measures; features = facility characteristics + volume (set A); set B adds two held-out quality measures.
* **Design 2 (secondary):** index from 8 outcome/safety/cost measures; features = characteristics + 3 care-process measures + 2 held-out measures.

Models: Logistic Regression, Decision Tree, Random Forest, XGBoost (+ majority-class baseline); hybrids: soft voting, CV-weighted voting, stacking.
Validation: stratified 80/20 hold-out; 5-fold CV grid search on the 80% (macro-F1); preprocessing inside the CV pipeline.
Metrics: accuracy, macro precision/recall/specificity/F1, ROC-AUC (OvR macro), PR-AUC (macro), Brier score, calibration, bootstrap CI, Low<->High error rate.
Explainability: TreeSHAP (XGBoost) - global and local.

## How to run
```bash
pip install -r requirements.txt
python run_pipeline.py            # ~15-25 min on 1 CPU; creates data/processed, outputs/figures|tables|models, outputs/results.json
python make_notebooks.py          # (optional) regenerate notebooks, then run them in Jupyter/Colab
streamlit run dashboard/app.py    # dashboard
```
Place the two raw CSVs in `data/raw/` as `irf_general_information.csv` and `irf_provider_data.csv`. Seed = 42 everywhere.

## Limitations
Cross-sectional public-reporting data; measures cover different reporting periods; index is a design choice (percentile/equal weights); categories are relative (terciles);
facility-level case-mix is not available; name-based flags are keyword heuristics; associations are not causal; no clinical use.

## Future scope
Add the Conditions file (case-mix), multi-year refreshes (temporal validation), hierarchical/ordinal models, probability calibration, fairness checks by ownership/region.
